# Temu 商品上架自动化

目标是准备并验收商品草稿，不是在未经确认的情况下最终发布。SKILL 只负责阶段编排、停止条件和人工确认；字段查找、值计算、点击、输入、上传、逐行核验和重载验收由脚本生成的动作和浏览器适配器完成。页面文案、控件和步骤可能变化，始终以当前可见页面为准；`listing.yaml` 只提供默认值、字段映射和同义词。

## 执行模式：SKILL 编排，脚本操作

不要把本文件下面的浏览器步骤当作需要模型逐项执行的点击清单。启动流程时先生成校验计划和动作队列：

```text
scripts/validate_listing.py <配置路径> --pack-dir <图片包目录> --json --plan-out <plan.json>
scripts/listing_workflow.py <配置路径> --plan <plan.json> --actions-out <actions.json>
scripts/listing_workflow.py <配置路径> --plan <plan.json> --state <state.json> --executor "<浏览器适配器命令>"
- 默认配置：`D:\project\temu-listing\config\listing.yaml`。若用户给出其他路径，优先使用用户路径。
- 配置相对路径以项目根目录（通常为 `D:\project\temu-listing`）解析，不以 skill 目录解析；`package_outer` 也可使用配置中明确的绝对路径。
- 先运行 `scripts/validate_listing.py <配置路径> --json` 检查 YAML、图片路径、数量和报价匹配规则，并生成本图片包唯一的执行计划。不要因验证失败而猜测路径或价格。执行计划中的 `brands`、`carousel_files`、`detail_files`、`package_outer`、`material_search_terms` 和 `material_cache_key` 是本任务后续步骤的唯一输入；同一图片包处理后续品牌时不得重新解析配置或重新推导标题、型号、SKU、价格和图片顺序。
- 手机型号配置在 `brands[].phone_models`；价格不再写在手机型号行中，而是从顶层 `pricing.quote_rows` 按首图材质编号和当前 `craft_code` 解析，再应用 `difference` 与 `suggested_retail_multiplier`。颜色配置在品牌级 `colors`，本次工艺配置在与 `brands` 平级的顶层 `craft_codes`。每个顶层工艺代码都会与每个品牌组合成独立商品，不从厂家 SKU 或 `defaults.sku` 解析价格。工艺名称由顶层 `craft_code_names` 映射。

```yaml
craft_codes:
  - "GY"
craft_code_names:
  "GY": "工艺名称"
brands:
  - brand: iPhone15ProMax
    title: "适用于iPhone15ProMax的手机壳"
    colors:
      - 银色
    phone_models:
      - phone_model: iPhone 15 Pro Max
pricing:
  difference: 0
  suggested_retail_multiplier: 8
  declaration_price_currency: store_currency
  suggested_retail_price_currency: USD
  quote_rows:
    - material_code: "005"
      craft_code: "GY"
      label: "康宁贴皮[光油]"
      price: 5.1
```

`validate_listing.py` 是唯一的输入校验和执行计划生成器。`listing_workflow.py` 读取该计划，解析默认值，计算报价、申报价、建议零售价、颜色编码、SKU、图片绑定和规格数量，并输出按依赖排序的 JSON 动作。动作执行器从 stdin 接收一条 action，返回 `{"ok":true,"evidence":{...}}`；非零退出、无效 JSON、`ok:false` 或缺少验收证据都必须停止。`--state` 支持断点续跑，已完成动作不会重复执行。

完整图片包任务使用总调度脚本。它只校验一次图片包，并按照校验计划中已经展开的“品牌/机型分组 × 当前颜色 × 工艺”逐个执行全部商品流程；登录、页面映射缓存和素材缓存保持图片包级复用，所有流程共用一个状态文件并在最终人工审核点停止：

```text
scripts/listing_batch.py <配置路径> --pack-dir <图片包目录> --plan-out <plan.json> --actions-out <actions.json>
scripts/listing_batch.py <配置路径> --pack-dir <图片包目录> --state <state.json> --executor "<浏览器适配器命令>"
```

`listing_workflow.py --task-index N` 只用于单个商品流程的小范围测试；总调度不得逐次手工拼接 `--task-index`，而应由 `listing_batch.py` 一次冻结并执行完整队列，避免任务遗漏、状态文件冲突和重复创建草稿。

执行阶段遇到输入超时、连接重置、CDP/WebSocket 断开、浏览器目标页关闭等连接类错误时，由脚本进行有限次幂等恢复：默认单动作最多尝试 2 次，单次执行器超时 90 秒，重试采用递增退避，可通过 `--max-attempts`、`--executor-timeout` 和 `--retry-backoff` 调整。动作若带有 `timeout_recovery.probe`，重试前必须向同一执行器发送 `type=probe_action_state` 的探测动作；只有探测证据明确显示目标状态尚未完成时才允许重试，已完成则直接记录为恢复完成，结果不明确或探测失败必须停止。每次尝试、恢复、失败和不确定状态都会写入 `--state`，并记录动作耗时，避免连接断开后重复创建草稿。

SKU 无法批量填写的行字段默认按每 20 行一个分块，仅在需要逐行处理的字段上分块；可通过 `--sku-chunk-size` 调整。表头价格、币种和 SKU 分类仍保持一次批量填写。
1. 使用 Browser 技能连接 `https://agentseller.temu.com/`。如果未登录，把浏览器交给用户登录；不要读取或代填凭据。遇到 CAPTCHA 必须停下询问用户。
2. 进入“商品管理 → 新建商品”（或当前页面中语义等价的入口）。每次点击、滚动或选择后获取新的 DOM 快照，确认页面状态再继续。
3. 读取 `form_labels`，用标签/占位符/可访问名称的精确匹配优先，数组中的其他文案作为回退；不要依赖脆弱的 CSS 类名或固定坐标。若当前页面没有匹配项，记录实际可见文案并暂停请求用户确认或调整配置。
4. 按页面当前顺序填写：素材语言；轮播图；商品名称；产地级联；材质/属性；规格；包装图片、类型、形状；敏感属性与体积重量。包装图片必须使用 `defaults.images.package_outer` 解析出的规范化绝对路径，并在上传完成后确认页面已出现预览缩略图。轮播图上传后如果平台自动同步商品素材图，只在页面仍要求时操作，不要重复上传。商品产地是两级必填级联：先选国家/地区，再选随之出现的省份；例如配置为中国广东时，必须分别确认输入框最终显示 `中国大陆` 和 `广东省`。只显示国家而省份仍为“请选择省份”属于未完成。
   - 敏感属性表格必须先填写表头的敏感属性、最长边、次长边、最短边和重量（按配置中实际存在的字段），确认这些表头控件均显示最终值且同一区域的“批量填写”按钮已启用后，只点击一次“批量填写”。敏感属性和体积重量属于同一个批量动作，不得先批量填写敏感属性、再批量填写体积重量，也不得逐行手填代替表头批量操作。操作后逐行读取敏感属性、尺寸和重量列，确认每个手机型号/颜色组合行都显示相同的预期值；不能以第一行已显示“否”或尺寸值推断其他行也已填写。若任一表头值未选中或按钮仍禁用，先修正表头控件，不要跳过批量填写。
5. 按执行计划的“品牌 × craft_code”顺序逐项创建独立商品草稿；同一品牌的不同 craft_code 必须创建不同商品，但复用同一图片、品牌和材质。若品牌项配置了 `title`，使用该完整标题；否则按模板生成。标题必须在图片包首图材质和 AI 图片特征描述就绪后生成，格式为 `适用于{brand}手机壳{material}{craft_codes}{desc}保护壳`，其中 `{craft_codes}` 使用 `craft_code_names` 中的工艺名称。手机型号、颜色、工艺代码、申报价格、建议零售价及币种直接读取预生成的队列项；图片包到位后，用首图图片编码末尾的材质编号、去掉 `1_` 后的完整图片编码和颜色编码生成 SKU。找不到型号、颜色、工艺代码、材质或 AI 描述时停下，不得回退到厂家 SKU、默认价格、固定描述或临时价格。
6. 对级联、弹窗、多选、素材中心等自定义组件先读取可见选项，再选择与配置值完全相同的选项；配置值与页面选项存在大小写、语言或括号差异时，只有用户明确确认后才能记录一次性映射并继续，不得自行近似选择。当前已由用户确认的页面映射与交互如下：
   - 手机型号配置 `iPhone 15` 对应页面候选 `iphone 15`；选择后确认规格表实际新增该行。
   - 主要材质配置 `PC` 对应页面展示 `PC PC(Polycarbonate)`：第一个 `PC` 是中文选项值，后面的 `PC(Polycarbonate)` 是英文注释。点击该候选后，确认输入框实际显示 `PC`。
   - 颜色输入 `银色` 后页面会展示可点击候选项；输入文字只代表筛选，必须再点击候选 `银色`，并确认规格表实际新增“银色”行。
   - 素材中心若提示图片已存在，按页面提示关闭后勾选已有素材并确认。
7. 图片上传属于向 Temu 传输本地文件。若本任务已有上传预授权，仅对素材缓存判定为 miss 的本地文件使用 file chooser 上传，无需再次人工同意；仍须在操作记录中列出实际上传的绝对路径、确认上传完成并检查页面预览缩略图。缓存命中只省略上传动作，不能省略当前草稿的素材搜索、选择、确认和预览核验。不要把路径输入普通文本框。
8. “下一步”只用于完成页面内分步校验。出现必填错误时读取错误文本，修正映射或让用户补充；不要绕过校验。
9. 品牌字段无需填写；除非以后配置中新增了用户明确提供的品牌值，否则始终保持为空。SKU 分类选择“单品”后，必须点击 **SKU 信息区域**的“批量填写”（不要误点敏感属性区域中同名但可能禁用的按钮），再确认实际组合行已经显示“单品”；只在表头控件中选中“单品”不算完成。若 `defaults.sku.fill_total_contents` 为 `false`，保留页面“共计内含”为空，不要为了消除提示而填入 1、重量或其他猜测值。
10. 对每个 SKU 组合行，读取该行的手机型号；价格按首图材质编号 + 当前任务项的顶层 `craft_code` 在 `pricing.quote_rows` 中匹配，申报价格为报价加 `difference`，建议零售价为申报价格乘 `suggested_retail_multiplier`。若同材质同工艺存在多个不同报价，必须由任务提供匹配的 `quote_label`，不得取第一行。颜色从当前品牌 `brands[].colors` 读取。先从首图解析材质编号和图片编号，再按 `【材质编号】【工艺代码】-【手机型号】-【颜色编码】-【图片编号】` 生成并填入“SKU货号”；`declaration_price` 填入“申报价格(CNY)”，`suggested_retail_price` 填入“建议零售价”，`suggested_retail_price_currency` 通过页面下拉候选选择。不要按一行内输入框的视觉顺序或索引猜字段；必须先用列标题、可访问名称或稳定的表单字段标识确认“共计内含”“建议零售价”“制造商建议零售价（适用于美国）”分别对应哪个控件。按配置币种选择页面完全匹配的候选并确认组合行最终同时显示价格和币种；“制造商建议零售价（适用于美国）”保持为空，`fill_total_contents: false` 时“共计内含”保持为空。不得把包装重量写入“共计内含”，也不得把建议零售价写入美国价格栏。型号/颜色/工艺规则、报价匹配或任一字段缺失、重复或冲突时停止。
11. 轮播图、SKU 预览图和详情图文是三个互相独立的绑定结果；任何一个完成都不能推断另外两个自动完成。对每个 SKU 组合行分别打开该行的“素材中心”，按配置选择预览素材（默认使用解析后轮播图的第一张）。素材搜索结果中只点击素材名称不会可靠选中图片；必须点击素材卡片的图片/缩略图，并确认“已选1个”且“确认”按钮已启用。关闭素材中心后，该 SKU 行必须由“素材中心”变为“预览”；每一行都要单独核验，不能只处理第一行。
12. 若配置启用 `defaults.images.detail.enabled`，点击“开始装修”，严格按解析出的轮播图顺序添加同等数量的“图片”组件。每张素材只新增一次“图片”组件，再点“从素材中心添加”；在素材搜索结果中点击卡片图片/缩略图，确认已选计数和“确认”按钮状态后提交选择。选择素材名称文本、打开素材中心或看到搜索结果都不算完成。每次返回编辑器后，必须确认当前组件已有图片预览且没有“请在右侧面板添加图片”，再处理下一张；不得生成多余的空组件、只绑定首图或重复同一张。最后确认组件数量和顺序与配置一致，再点击详情编辑器中的“保存”。该“保存”不是最终商品创建，不替代最终提交前的人审。
13. 勾选“商品合规声明”是每个品牌上架流程的必做步骤，不是可选的人审动作。到达 SKU/预览/提交页后，定位“我已阅读并同意《商品合规声明》”前面的复选框并勾选；禁止点击 `《商品合规声明》` 链接。优先直接操作 `role=checkbox` 对应的真实控件；若真实 `input` 的可点击区域为 `0×0` 或直接点击超时，则在同一复选框标签内点击可见的小方框容器（例如 `data-testid=beast-core-checkbox-checkIcon`），不要把交互失败当成已经勾选。操作后必须读取真实控件的 `checked` 状态并确认为 `true`。
14. 点击“保存草稿”并确认页面出现“保存成功”后，关闭成功提示并重新载入同一草稿进行落库验收。每个品牌必须独立核验：国家和省份均有值；轮播图数量符合配置；每个 SKU 行都显示“预览”；敏感属性、尺寸和重量列每个组合行都显示预期值（包括通过同一表头“敏感属性 + 体积重量”后一次“批量填写”设置的非敏感品）；SKU 分类、申报价格、建议零售价、币种和 SKU 货号正确；“共计内含”和美国价格栏符合配置；详情图片组件数量及顺序正确；商品合规声明为已勾选。任何点击超时、弹窗未确认、编辑器未保存或重载后字段回退都属于未完成，必须修正或明确报告，不能以“已操作过”代替验收。当前品牌保存成功、没有上传/弹窗/未落库字段，且重载验收已启动或已完成后，可在独立后台标签页为队列中的下一品牌打开“新建商品”并等待类目页或基础信息页 ready；预热只允许导航和页面加载，禁止提前填写、上传、选择素材或提交。下一品牌真正开始时必须绑定并复核该预热标签页，不能使用当前品牌的草稿页。
15. 保存草稿和勾选声明都不代表获准创建。汇总实际填写值、图片文件、每个型号的两种价格及币种和未解决字段后停下，只有用户明确即时确认后才点击最终“创建/提交/立即提交”。

导航类动作的点击超时按“不确定状态”处理，不得立即重复点击。执行器必须先重新读取当前页和 `user.openTabs()`：若出现带 `productDraftId` 的商品发布页，或目标表单已出现（例如“商品轮播图”），则在探测 evidence 中返回 `already_applied=true` 或 `target_present=true`，脚本会将动作标记为成功并继续；只有确认仍停留在原页面且没有目标标签时，才允许一次重试。重复点击可能创建多个草稿。

脚本动作类型包括 `validate_plan`、`ensure_authenticated`、`open_new_product`、`fill_basic_fields`、`fill_sku_table`、`bind_detail_images`、`confirm_compliance_statement`、`save_and_reload_verify` 和 `await_submission_confirmation`；连接类失败恢复时还会发送内部 `probe_action_state` 探测动作。下面各节只定义阶段语义、业务约束和停止条件，具体 selector、等待、批量填写、逐行核验和上传细节不得由模型重新实现。执行器不得调用接口、注入脚本或写隐藏字段绕过页面验证。

## 一、输入、校验与不可变数据

### 1. 配置入口

提交后的合规信息（欧代、土代/GPSR 等）属于独立模块，请改用 `temu-compliance-automation` Skill，从首页侧栏“合规服务→合规中心→商品合规信息填写”进入；只有配置有明确值且用户另行确认时才进入，不要在新建商品页猜填。

### 2. 校验与执行计划

先运行：

```text
scripts/validate_listing.py <配置路径> --json
```

校验 YAML、图片路径、图片数量、报价表和价格公式。校验失败时停止，不猜测路径或价格。

校验输出的 `brands`、`pricing`、`carousel_files`、`detail_files`、`package_outer`、`material_search_terms` 和 `material_cache_key` 是本图片包任务的唯一输入。后续品牌不得重新解析配置、读取旧型号价格或回退到厂家 SKU。

执行队列按以下顺序展开：

```text
品牌 × 当前品牌颜色 × craft_code
```

同一品牌的不同颜色必须是不同商品；每个任务只有一个 `color`（以及单元素 `colors`）。若配置多个工艺，再对每个工艺分别生成商品。

### 3. 报价、标题与 SKU

- 报价统一来自顶层 `pricing.quote_rows`，不从 `phone_models` 读取。
- 按首图 `material_code`、当前 `craft_code`，以及必要的 `label`（如苹果/安卓）精确匹配报价；缺失、重复、冲突或非数字时停止。
- 价格公式：`declaration_price = quote + difference`；`suggested_retail_price = declaration_price × suggested_retail_multiplier`。
- 币种从 `pricing` 读取并按页面完全匹配的选项选择。
- 标题默认使用 `适用于{brand}手机壳{material}{craft_codes}{desc}保护壳`。其中品牌、首图材质元数据、工艺来自当前任务；`desc` 必须来自图片特征 AI 或任务 payload，不能使用固定测试词。
- 图片和任务数据就绪后生成 SKU，格式遵循 `sku_code_rule`，不得使用厂家 SKU 或旧表回填。

### 4. 图片包规则

- 轮播图固定为五张，按文件名序号 `1`、`2`、`3`、`4`、`5` 排序。
- 首图必须是 `1_<图片编码>.<扩展名>`；其余文件名只允许 `2`、`3`、`4`、`5` 加扩展名。
- 去掉首图的 `1_` 和扩展名得到 `image_id`；文件名末尾三位数字是 `material_code`。
- 缺号、重号、少于五张、首图缺少材质编号或文件格式不符时停止；不得读取或依赖 `manifest.images`。
- `package_outer` 必须解析为单个可读文件。轮播素材、详情素材和外包装图片是三个独立字段；外包装图不能因素材缓存命中而跳过。

### 5. 配置约束

- `brands[].brand` 只填纯品牌名；同一品牌只保留一个品牌项，型号统一放在该项的 `phone_models`。
- 颜色配置在品牌级 `colors`；本次工艺来自顶层 `craft_codes`，名称由 `craft_code_names` 映射。
- `material_codes` 只用于首图元数据、标题和 SKU 前缀；Temu“主要材质”始终使用 `defaults.attributes.main_material`（当前为 `PC`），不能把图片材质名回填到该属性。
- `attribute_names` 可单独配置颜色、工艺和材质字段名称。
- 用户已明确授权本任务上传文件时，可继续使用文件选择器上传，无需重复询问；仍要记录绝对路径并核验预览。

报价同步脚本 `tools/sync_quotes.py` 只更新 `pricing.source` 和 `pricing.quote_rows`，保留差价、倍率等本地公式；报价单至少每日同步一次。同步后必须重新运行校验，报价缺失则暂停上架。

## 二、浏览器前的一次性准备

以下状态在整个图片包任务中复用，不要每个品牌重新推理：

1. 冻结执行队列、每个任务的申报价格、建议零售价、币种和 SKU 规则。
2. 建立“配置键 → 页面标签/选项/操作方式”映射缓存。页面状态相同且缓存命中时直接复用；控件缺失、候选变化或验收失败时才使对应缓存失效并重新读取。
3. 建立素材缓存，作用域为“当前店铺/Chrome 配置 + `material_cache_key`”：`unknown` 表示未检查，`ready` 表示所有素材可搜索、可选且顺序核验通过，`miss` 表示只补传精确缺失文件后重新核验。缓存命中只省略上传动作，不能省略当前草稿的搜索、选择和预览确认；不同店铺或 Chrome 配置不得共享 `ready`。
4. 为每个任务记录六段耗时：导航/类目、轮播素材、基础字段、SKU、详情、保存与重载验收；同时记录素材 cache hit/miss。

## 三、浏览器流程语义（由脚本动作执行）

本节是动作执行器的业务契约和验收标准，不是给模型的手工操作步骤。SKILL 只按动作队列调用执行器并检查其返回的 evidence；没有执行器时只能生成队列，不能声称已完成上架。

### 1. 登录与进入表单

1. 使用 Browser 技能打开 `https://agentseller.temu.com/`。
2. 未登录时交给用户登录，不读取或代填凭据；出现 CAPTCHA、风控或敏感资料要求时立即停止。
3. 进入“商品管理 → 新建商品”（或当前页面语义等价入口）。每次点击、输入、滚动或选择后，都重新读取 DOM/页面状态。

### 2. 类目与字段定位

- 优先按 `form_labels` 的 label、placeholder、可访问名称和 role 精确匹配，其他文案仅作回退。
- 不依赖脆弱 CSS 类名、固定坐标或输入框视觉顺序。
- 类目未唯一匹配、字段缺失或页面出现未知必填项时，记录实际文案并暂停。
- “下一步”只用于完成当前页面校验，不得绕过错误。点击若报告 CDP/输入超时，先探测新标签页、`productDraftId` 和目标表单；目标已出现时不要重试，避免重复创建草稿。

### 3. 基础信息与规格

按当前页面顺序填写：素材语言、轮播图、标题、产地、主要材质、手机型号、当前颜色、包装图片/类型/形状、敏感属性、尺寸和重量。

- 产地是两级级联：先确认国家/地区，再确认省份；只显示国家而省份仍为“请选择省份”不算完成。
- 主要材质必须选择 `PC`；图片首图材质编码不能替代该属性。
- 当前任务只选择当前单色，不得把品牌的全部颜色合并到一个商品。
- 敏感属性和体积重量优先使用各自表头的“批量填写”：选择值、确认按钮启用、点击批量填写后，再逐行核验所有组合行。

已确认的页面映射：

- 配置 `iPhone 15` 对应页面候选 `iphone 15`；选择后必须确认规格表新增该型号。
- `PC` 对应页面展示 `PC PC(Polycarbonate)`；选择后输入框最终值必须为 `PC`。
- 颜色允许直接输入；必须确认输入框最终值和规格表新增的颜色行。候选项存在时可点击规范化，缺失时不得擅自改名或近似映射。
- 素材中心提示文件已存在时，关闭提示后勾选已有素材并确认。

### 4. SKU 信息表

SKU 表只产生“全部手机型号 × 当前颜色”的组合行。

1. SKU 分类在表头选择“单品”，点击 **SKU 信息区域** 的“批量填写”，再逐行确认已显示“单品”；不能只选表头，也不能误点敏感属性区域的同名按钮。
2. 申报价格、SKU 分类、建议零售价均在表头设置后分别点击对应的“批量填写”，禁止逐行重复填写。建议零售价必须同时完成两项：填写价格数值，并在“建议零售价单位”下拉框选择 `listing.yaml` 中 `pricing.suggested_retail_price_currency` 配置的单位（当前配置为 `USD`）；不能只填数值而遗漏单位。批量填写后要逐行核验价格和单位均已落到 SKU 行。
3. 按当前任务的材质、工艺、单色、手机型号和图片编号生成每行 SKU 货号：

   ```text
   【材质编号】【工艺代码】-【手机型号】-【颜色编码】-【图片编号】
   ```

4. 建议零售价币种必须与配置一致；“制造商建议零售价（适用于美国）”保持为空；`fill_total_contents: false` 时“共计内含”保持为空。不得把包装重量或建议零售价写入错误字段。

### 5. SKU 预览图与详情图文

- SKU 预览图不使用批量填写。每个组合行都必须单独打开该行素材中心，点击素材卡片图片/缩略图（不是名称文本），确认“已选1个”和“确认”按钮可用；关闭后该行必须从“素材中心”变为“预览”。
- 默认每行绑定已核验轮播图的第一张，并覆盖全部组合行；不能只处理第一行或前两行。
- 若启用详情图文，按轮播图顺序添加同等数量的“图片”组件，复用同一份已确认轮播素材。每个组件只添加一次图片并确认预览存在，最后点击详情编辑器“保存”。
- 详情素材弹窗为空时依次执行：清空搜索词 → 关闭“仅展示可用” → 刷新 → 重开。仍为空则报告素材中心加载/可用性问题，不重复上传轮播图，也不能把空列表当作完成。

### 6. 合规声明、草稿保存与停止

1. 到达 SKU/预览/提交页后，定位“我已阅读并同意《商品合规声明》”前面的复选框。
2. 优先操作真实 `role=checkbox`/`input`；若控件为 `0×0` 或直接点击超时，点击同一标签内可见的小方框容器（如 `data-testid=beast-core-checkbox-checkIcon`）。禁止点击声明链接。
3. 读取真实控件 `checked` 状态，只有 `checked=true` 才算完成。
4. 点击“保存草稿”，确认出现“保存成功”，关闭提示并重载同一草稿。
5. 重载后逐项验收：国家和省份、轮播图数量、PC 材质、敏感属性、SKU 分类、两种价格及币种、SKU 货号、预览图覆盖率、详情组件顺序、合规勾选状态。
6. 汇总已填值、图片、价格、币种和未解决字段后停止。保存草稿或勾选声明不等于获准创建；最终“创建/提交/立即提交”必须等待用户即时确认。

合规信息（欧代、土代/GPSR 等）属于提交后的独立模块，只有配置有明确值且用户另行确认时才进入；不要在新建商品页猜填。

## 四、状态驱动等待与回退

- 不使用固定时长 sleep 作为正常流程。动作后立即读取对应完成条件：弹窗出现/消失、按钮启用、输入框最终值、规格或 SKU 行出现、上传进度消失且缩略图数量正确、URL/步骤标题变化或“保存成功”出现。
- 等待期间只观察，不重复点击；超时后重新读取 DOM 和可见错误文本，按当前步骤的重试上限处理，不用更长等待掩盖失败。
- 页面稳定且映射缓存命中时执行确定性动作；只有控件无法唯一匹配、候选变化、页面报错或验收失败时才进入 agent/人工回退。回退成功后更新缓存。

## 五、配置自适应与安全停止

页面实际字段优先于旧配置。发现标签、选项、图片路径或字段结构变化时，先记录“配置键 → 实际页面字段/选项”的差异；只有用户同意才回写 `listing.yaml`，保留原值并用注释或 `overrides` 记录，不删除未知配置项，也不把一次性文案硬编码成永久规则。

出现以下任一情况必须停止并给出缺口清单：

- 未登录、CAPTCHA、风控或要求敏感资料；
- 类目、字段、选项或颜色无法唯一匹配；
- 图片缺失、格式不符、素材中心无法确认或预览不完整；
- 报价、价格公式、颜色、工艺、图片材质编码或 SKU 不明确；
- 保存/重载验收失败；
- 最终提交前未获得用户即时确认。

不得通过接口、脚本注入或隐藏字段绕过页面验证。

详细配置键和解析约定见 [references/listing-schema.md](references/listing-schema.md)。
