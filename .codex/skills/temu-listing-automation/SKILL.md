# Temu 商品上架自动化

使用本技能时，目标是准备好一个可提交的商品草稿，而不是未经确认直接发布。页面文案和步骤可能变化，必须以当前可见页面为准；`listing.yaml` 只是默认值和标签同义词。

## 输入与配置

- 默认配置：`D:\project\temu-listing-ops\config\listing.yaml`。若用户给出其他路径，优先使用用户路径。
- 配置相对路径以项目根目录（通常为 `D:\project\temu-listing-ops`）解析，不以 skill 目录解析；`package_outer` 也可使用配置中明确的绝对路径。
- 先运行 `scripts/validate_listing.py <配置路径> --json` 检查 YAML、图片路径、数量和手机型号价格规则，并生成本图片包唯一的执行计划。不要因验证失败而猜测路径或价格。执行计划中的 `brands`、`carousel_files`、`detail_files`、`package_outer`、`material_search_terms` 和 `material_cache_key` 是本任务后续步骤的唯一输入；同一图片包处理后续品牌时不得重新解析配置或重新推导标题、型号、SKU、价格和图片顺序。
- 申报价格、建议零售价和建议零售价币种必须与品牌标题组、手机型号配置在同一条规则中；颜色配置在品牌级 `colors`，本次工艺配置在与 `brands` 平级的顶层 `craft_codes`。每个顶层工艺代码都会与每个品牌组合成独立商品，不在 `phone_models` 中重复，不再从厂家 SKU 或 `defaults.sku` 解析价格。工艺名称由顶层 `craft_code_names` 映射。

```yaml
craft_codes:
  - "GY"
craft_code_names:
  "GY": "工艺名称"
brands:
  - brand: iPhone15ProMax
    title: "适用于iPhone15ProMax的手机壳"
    colors:
      - 银色
    phone_models:
      - phone_model: iPhone 15 Pro Max
        declaration_price: "22"
        suggested_retail_price: "58"
        suggested_retail_price_currency: USD
```

- 图片包固定包含五张图片，文件名必须使用数字顺序前缀 `1_` 到 `5_`；首图格式为 `1_{图片编码}`，例如 `1_yzy2026082601005.jpg`，其余四张分别以 `2_`、`3_`、`4_`、`5_` 开头。代码按数字前缀排序，不读取或依赖 `manifest.images`。`listing.yaml` 无需记录该图片包的五个文件名；使用 `images.task_injected: true` 或 `carousel.files: []`，运行时从图片包目录自动发现。`package_outer` 仍必须是单个可读文件。
- 图片包 `1_` 文件是材质编码图：去掉 `1_` 和扩展名后的文本作为 `image_id`，例如 `1_yzy2026082601005.jpg` 得到 `yzy2026082601005`；图片编码末尾三位数字解析为 `material_code`。文件名缺少 `1_`～`5_`、序号重复、少于五张或首图图片编码缺少材质编号时必须停止。
- `attribute_names` 允许在 `listing.yaml` 单独配置颜色、工艺、材质类别名。商品标题使用 `适用于{brand}手机壳{material}{craft_codes}{desc}保护壳`；品牌、材质和工艺由当前配置/首图匹配，`desc` 必须由图片特征 AI 生成或由任务 payload 注入，不能用固定测试词或猜测替代。
- 不要把账号、密码、验证码或浏览器存储写入配置文件。
- 配置未指定的字段默认留空，不要为了提高填写率或消除提示而猜填品牌、属性、规格、价格或其他值。
- 本技能支持任务级上传预授权：若用户已明确授权本次/本任务上传文件，后续上传无需再次人工确认；仍须使用文件选择器，并保留实际上传文件清单供复核。

## 图片包级执行计划与缩时约束

开始操作浏览器前一次性完成以下准备，并在整个图片包任务内保留状态；不要每处理一个品牌都重新思考这些内容：

1. 从校验脚本 JSON 输出建立有序“品牌 × craft_code”执行队列；每个工艺代码都生成独立商品，复用同一图片、品牌和材质。每个队列项预先列出最终标题、craft_code、品牌级 colors、全部手机型号、申报价格、建议零售价和币种。SKU 货号留到图片包到位后按 `sku_code_rule` 生成。计划生成后保持不可变；页面执行阶段只读取，不再补算或回退。
2. 建立任务内映射缓存：`配置键 → 当前页面标签/选项/操作方式`。第一品牌确认过的类目路径、标签、大小写映射和控件操作可直接复用于后续品牌；只有控件缺失、候选变化或操作后状态不符时才使对应缓存项失效并重新读取当前页面。不要为相同页面状态再次调用 agent/LLM。
3. 素材缓存以“当前店铺/Chrome 配置 + material_cache_key”为作用域，初始状态为 `unknown`。第一品牌打开素材中心后，先按 `material_search_terms` 逐个精确搜索已有素材，只把确实缺失的文件一次性批量上传；全部素材可搜索、可选且顺序核验通过后标为 `ready`。后续品牌缓存为 `ready` 时只能搜索并选择已有素材，不再点“本地上传”；若某个精确文件名找不到，才把该文件标为 miss 并只补传缺失项，然后重新核验。不同店铺、不同 Chrome 配置或不同 `material_cache_key` 不得共享 ready 状态。
4. 外包装图片通常是商品表单的独立本地上传字段，不因轮播素材缓存为 ready 而跳过；每个品牌仍必须看到该草稿自己的外包装预览。详情图文只复用素材中心中已确认的轮播素材，不重复上传文件。
5. 记录每个品牌的 `导航/类目`、`轮播素材`、`基础字段`、`SKU`、`详情`、`保存与重载验收` 六段起止时间，以及素材 cache hit/miss；任务结束时汇总，以便判断真实瓶颈。

## 浏览器流程

1. 使用 Browser 技能连接 `https://agentseller.temu.com/`。如果未登录，把浏览器交给用户登录；不要读取或代填凭据。遇到 CAPTCHA 必须停下询问用户。
2. 进入“商品管理 → 新建商品”（或当前页面中语义等价的入口）。每次点击、滚动或选择后获取新的 DOM 快照，确认页面状态再继续。
3. 读取 `form_labels`，用标签/占位符/可访问名称的精确匹配优先，数组中的其他文案作为回退；不要依赖脆弱的 CSS 类名或固定坐标。若当前页面没有匹配项，记录实际可见文案并暂停请求用户确认或调整配置。
4. 按页面当前顺序填写：素材语言；轮播图；商品名称；产地级联；材质/属性；规格；包装图片、类型、形状；敏感属性、尺寸、重量。包装图片必须使用 `defaults.images.package_outer` 解析出的规范化绝对路径，并在上传完成后确认页面已出现预览缩略图。轮播图上传后如果平台自动同步商品素材图，只在页面仍要求时操作，不要重复上传。商品产地是两级必填级联：先选国家/地区，再选随之出现的省份；例如配置为中国广东时，必须分别确认输入框最终显示 `中国大陆` 和 `广东省`。只显示国家而省份仍为“请选择省份”属于未完成。
   - 敏感属性表格必须优先使用表头批量操作，避免只填到第一条组合行：打开敏感属性表头下拉，选择“否”（或配置要求的其他值），确认表头控件已显示所选值且“批量填写”按钮已启用，再点击该区域的“批量填写”。操作后逐行读取敏感属性列，确认每个手机型号/颜色组合行都显示相同的预期值；不能以第一行已显示“否”推断其他行也已填写。若表头选择后按钮仍禁用，先检查是否真的选中了“否”，不要手动跳过批量填写。
5. 按执行计划的“品牌 × craft_code”顺序逐项创建独立商品草稿；同一品牌的不同 craft_code 必须创建不同商品，但复用同一图片、品牌和材质。若品牌项配置了 `title`，使用该完整标题；否则按模板生成。标题必须在图片包首图材质和 AI 图片特征描述就绪后生成，格式为 `适用于{brand}手机壳{material}{craft_codes}{desc}保护壳`，其中 `{craft_codes}` 使用 `craft_code_names` 中的工艺名称。手机型号、颜色、工艺代码、申报价格、建议零售价及币种直接读取预生成的队列项；图片包到位后，用首图图片编码末尾的材质编号、去掉 `1_` 后的完整图片编码和颜色编码生成 SKU。找不到型号、颜色、工艺代码、材质或 AI 描述时停下，不得回退到厂家 SKU、默认价格、固定描述或临时价格。
6. 对级联、弹窗、多选、素材中心等自定义组件先读取可见选项，再选择与配置值完全相同的选项；配置值与页面选项存在大小写、语言或括号差异时，只有用户明确确认后才能记录一次性映射并继续，不得自行近似选择。当前已由用户确认的页面映射与交互如下：
   - 手机型号配置 `iPhone 15` 对应页面候选 `iphone 15`；选择后确认规格表实际新增该行。
   - 主要材质配置 `PC` 对应页面展示 `PC PC(Polycarbonate)`：第一个 `PC` 是中文选项值，后面的 `PC(Polycarbonate)` 是英文注释。点击该候选后，确认输入框实际显示 `PC`。
   - 颜色输入 `银色` 后页面会展示可点击候选项；输入文字只代表筛选，必须再点击候选 `银色`，并确认规格表实际新增“银色”行。
   - 素材中心若提示图片已存在，按页面提示关闭后勾选已有素材并确认。
7. 图片上传属于向 Temu 传输本地文件。若本任务已有上传预授权，仅对素材缓存判定为 miss 的本地文件使用 file chooser 上传，无需再次人工同意；仍须在操作记录中列出实际上传的绝对路径、确认上传完成并检查页面预览缩略图。缓存命中只省略上传动作，不能省略当前草稿的素材搜索、选择、确认和预览核验。不要把路径输入普通文本框。
8. “下一步”只用于完成页面内分步校验。出现必填错误时读取错误文本，修正映射或让用户补充；不要绕过校验。
9. 品牌字段无需填写；除非以后配置中新增了用户明确提供的品牌值，否则始终保持为空。SKU 分类选择“单品”后，必须点击 **SKU 信息区域**的“批量填写”（不要误点敏感属性区域中同名但可能禁用的按钮），再确认实际组合行已经显示“单品”；只在表头控件中选中“单品”不算完成。若 `defaults.sku.fill_total_contents` 为 `false`，保留页面“共计内含”为空，不要为了消除提示而填入 1、重量或其他猜测值。
10. 对每个 SKU 组合行，读取该行的手机型号，并按当前品牌 `brands[].phone_models[]` 的型号匹配价格；工艺从当前任务项的顶层 `craft_code` 读取，颜色从当前品牌 `brands[].colors` 读取。先从首图解析材质编号和图片编号，再按 `【材质编号】【工艺代码】-【手机型号】-【颜色编码】-【图片编号】` 生成并填入“SKU货号”；`declaration_price` 填入“申报价格(CNY)”，`suggested_retail_price` 填入“建议零售价”，`suggested_retail_price_currency` 通过页面下拉候选选择。不要按一行内输入框的视觉顺序或索引猜字段；必须先用列标题、可访问名称或稳定的表单字段标识确认“共计内含”“建议零售价”“制造商建议零售价（适用于美国）”分别对应哪个控件。按配置币种选择页面完全匹配的候选并确认组合行最终同时显示价格和币种；“制造商建议零售价（适用于美国）”保持为空，`fill_total_contents: false` 时“共计内含”保持为空。不得把包装重量写入“共计内含”，也不得把建议零售价写入美国价格栏。型号/颜色/工艺规则或任一字段缺失、重复或冲突时停止。
11. 轮播图、SKU 预览图和详情图文是三个互相独立的绑定结果；任何一个完成都不能推断另外两个自动完成。对每个 SKU 组合行分别打开该行的“素材中心”，按配置选择预览素材（默认使用解析后轮播图的第一张）。素材搜索结果中只点击素材名称不会可靠选中图片；必须点击素材卡片的图片/缩略图，并确认“已选1个”且“确认”按钮已启用。关闭素材中心后，该 SKU 行必须由“素材中心”变为“预览”；每一行都要单独核验，不能只处理第一行。
12. 若配置启用 `defaults.images.detail.enabled`，点击“开始装修”，严格按解析出的轮播图顺序添加同等数量的“图片”组件。每张素材只新增一次“图片”组件，再点“从素材中心添加”；在素材搜索结果中点击卡片图片/缩略图，确认已选计数和“确认”按钮状态后提交选择。选择素材名称文本、打开素材中心或看到搜索结果都不算完成。每次返回编辑器后，必须确认当前组件已有图片预览且没有“请在右侧面板添加图片”，再处理下一张；不得生成多余的空组件、只绑定首图或重复同一张。最后确认组件数量和顺序与配置一致，再点击详情编辑器中的“保存”。该“保存”不是最终商品创建，不替代最终提交前的人审。
13. 勾选“商品合规声明”是每个品牌上架流程的必做步骤，不是可选的人审动作。到达 SKU/预览/提交页后，定位“我已阅读并同意《商品合规声明》”前面的复选框并勾选；禁止点击 `《商品合规声明》` 链接。优先直接操作 `role=checkbox` 对应的真实控件；若真实 `input` 的可点击区域为 `0×0` 或直接点击超时，则在同一复选框标签内点击可见的小方框容器（例如 `data-testid=beast-core-checkbox-checkIcon`），不要把交互失败当成已经勾选。操作后必须读取真实控件的 `checked` 状态并确认为 `true`。
14. 点击“保存草稿”并确认页面出现“保存成功”后，关闭成功提示并重新载入同一草稿进行落库验收。每个品牌必须独立核验：国家和省份均有值；轮播图数量符合配置；每个 SKU 行都显示“预览”；敏感属性列每个组合行都显示预期值（包括通过表头“否”+“批量填写”设置的非敏感品）；SKU 分类、申报价格、建议零售价、币种和 SKU 货号正确；“共计内含”和美国价格栏符合配置；详情图片组件数量及顺序正确；商品合规声明为已勾选。任何点击超时、弹窗未确认、编辑器未保存或重载后字段回退都属于未完成，必须修正或明确报告，不能以“已操作过”代替验收。当前品牌保存成功、没有上传/弹窗/未落库字段，且重载验收已启动或已完成后，可在独立后台标签页为队列中的下一品牌打开“新建商品”并等待类目页或基础信息页 ready；预热只允许导航和页面加载，禁止提前填写、上传、选择素材或提交。下一品牌真正开始时必须绑定并复核该预热标签页，不能使用当前品牌的草稿页。
15. 保存草稿和勾选声明都不代表获准创建。汇总实际填写值、图片文件、每个型号的两种价格及币种和未解决字段后停下，只有用户明确即时确认后才点击最终“创建/提交/立即提交”。

## 状态驱动等待

- 不使用固定时长的“想一想”或无条件 sleep 作为正常流程步骤。点击、输入、上传、确认或切换页面后，立即读取新的 DOM/页面状态，并等待与动作对应的完成条件：目标弹窗出现或消失、按钮由禁用变为启用、输入框显示最终值、规格/SKU 行出现、上传进度消失且缩略图数量正确、URL/步骤标题变化、或“保存成功”出现。
- 等待期间只观察对应状态，不重复点击。达到条件立即继续，不等满超时时间；到达该动作的超时时间仍未满足时，重新抓取 DOM 和可见错误文本，最多按当前步骤定义重试，不得用更长固定等待掩盖失败。
- 页面状态稳定且任务内映射缓存命中时直接执行确定性动作；只有控件无法唯一匹配、候选变化、页面报错或状态验收失败时才进入分析/agent 回退。回退成功后更新本任务的对应映射缓存，后续品牌复用。

## 配置自适应与回写

页面实际字段优先于旧配置。发现标签、选项值、图片路径或字段结构变化时，先建立“配置键 → 实际页面字段/选项”的映射并展示差异；只有用户同意时才回写 `listing.yaml`，保留原值并以注释或 `overrides` 记录差异；不要删除未知配置项，也不要把一次性文案硬编码成永久规则。

提交后的合规信息（欧代、土代/GPSR 等）属于独立模块：只有配置有明确值且用户另行确认时才进入，不要在新建商品页猜填。

## 安全停止条件

未登录、出现 CAPTCHA/风控、字段无法唯一匹配、图片缺失或格式不符、价格/SKU 不明确、页面要求敏感资料、或最终提交前未获得即时确认时，停止并给出缺口清单。不要通过接口、脚本注入或隐藏字段绕过页面验证。

详细的配置键与解析约定见 [references/listing-schema.md](references/listing-schema.md)。
