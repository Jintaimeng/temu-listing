# Temu 商品上架自动化

目标是准备并验收商品草稿，不是在未经确认的情况下最终发布。页面文案、控件和步骤可能变化，始终以当前可见页面为准；`listing.yaml` 只提供默认值、字段映射和同义词。

## 一、输入、校验与不可变数据

### 1. 配置入口

- 默认配置为 `D:\project\temu-listing-ops\config\listing.yaml`；用户指定其他路径时优先使用用户路径。
- 配置相对路径按项目根目录（通常是 `D:\project\temu-listing-ops`）解析，不按 skill 目录解析；`package_outer` 可使用明确的绝对路径。
- 不把账号、密码、验证码或浏览器存储写入配置。
- 未配置的字段保持为空，不得猜填品牌、规格、属性、价格或其他值。

### 2. 校验与执行计划

先运行：

```text
scripts/validate_listing.py <配置路径> --json
```

校验 YAML、图片路径、图片数量、报价表和价格公式。校验失败时停止，不猜测路径或价格。

校验输出的 `brands`、`pricing`、`carousel_files`、`detail_files`、`package_outer`、`material_search_terms` 和 `material_cache_key` 是本图片包任务的唯一输入。后续品牌不得重新解析配置、读取旧型号价格或回退到厂家 SKU。

执行队列按以下顺序展开：

```text
品牌 × 当前品牌颜色 × craft_code
```

同一品牌的不同颜色必须是不同商品；每个任务只有一个 `color`（以及单元素 `colors`）。若配置多个工艺，再对每个工艺分别生成商品。

### 3. 报价、标题与 SKU

- 报价统一来自顶层 `pricing.quote_rows`，不从 `phone_models` 读取。
- 按首图 `material_code`、当前 `craft_code`，以及必要的 `label`（如苹果/安卓）精确匹配报价；缺失、重复、冲突或非数字时停止。
- 价格公式：`declaration_price = quote + difference`；`suggested_retail_price = declaration_price × suggested_retail_multiplier`。
- 币种从 `pricing` 读取并按页面完全匹配的选项选择。
- 标题默认使用 `适用于{brand}手机壳{material}{craft_codes}{desc}保护壳`。其中品牌、首图材质元数据、工艺来自当前任务；`desc` 必须来自图片特征 AI 或任务 payload，不能使用固定测试词。
- 图片和任务数据就绪后生成 SKU，格式遵循 `sku_code_rule`，不得使用厂家 SKU 或旧表回填。

### 4. 图片包规则

- 轮播图固定为五张，按文件名序号 `1`、`2`、`3`、`4`、`5` 排序。
- 首图必须是 `1_<图片编码>.<扩展名>`；其余文件名只允许 `2`、`3`、`4`、`5` 加扩展名。
- 去掉首图的 `1_` 和扩展名得到 `image_id`；文件名末尾三位数字是 `material_code`。
- 缺号、重号、少于五张、首图缺少材质编号或文件格式不符时停止；不得读取或依赖 `manifest.images`。
- `package_outer` 必须解析为单个可读文件。轮播素材、详情素材和外包装图片是三个独立字段；外包装图不能因素材缓存命中而跳过。

### 5. 配置约束

- `brands[].brand` 只填纯品牌名；同一品牌只保留一个品牌项，型号统一放在该项的 `phone_models`。
- 颜色配置在品牌级 `colors`；本次工艺来自顶层 `craft_codes`，名称由 `craft_code_names` 映射。
- `material_codes` 只用于首图元数据、标题和 SKU 前缀；Temu“主要材质”始终使用 `defaults.attributes.main_material`（当前为 `PC`），不能把图片材质名回填到该属性。
- `attribute_names` 可单独配置颜色、工艺和材质字段名称。
- 用户已明确授权本任务上传文件时，可继续使用文件选择器上传，无需重复询问；仍要记录绝对路径并核验预览。

报价同步脚本 `tools/sync_quotes.py` 只更新 `pricing.source` 和 `pricing.quote_rows`，保留差价、倍率等本地公式；报价单至少每日同步一次。同步后必须重新运行校验，报价缺失则暂停上架。

## 二、浏览器前的一次性准备

以下状态在整个图片包任务中复用，不要每个品牌重新推理：

1. 冻结执行队列、每个任务的申报价格、建议零售价、币种和 SKU 规则。
2. 建立“配置键 → 页面标签/选项/操作方式”映射缓存。页面状态相同且缓存命中时直接复用；控件缺失、候选变化或验收失败时才使对应缓存失效并重新读取。
3. 建立素材缓存，作用域为“当前店铺/Chrome 配置 + `material_cache_key`”：`unknown` 表示未检查，`ready` 表示所有素材可搜索、可选且顺序核验通过，`miss` 表示只补传精确缺失文件后重新核验。缓存命中只省略上传动作，不能省略当前草稿的搜索、选择和预览确认；不同店铺或 Chrome 配置不得共享 `ready`。
4. 为每个任务记录六段耗时：导航/类目、轮播素材、基础字段、SKU、详情、保存与重载验收；同时记录素材 cache hit/miss。

## 三、浏览器流程

### 1. 登录与进入表单

1. 使用 Browser 技能打开 `https://agentseller.temu.com/`。
2. 未登录时交给用户登录，不读取或代填凭据；出现 CAPTCHA、风控或敏感资料要求时立即停止。
3. 进入“商品管理 → 新建商品”（或当前页面语义等价入口）。每次点击、输入、滚动或选择后，都重新读取 DOM/页面状态。

### 2. 类目与字段定位

- 优先按 `form_labels` 的 label、placeholder、可访问名称和 role 精确匹配，其他文案仅作回退。
- 不依赖脆弱 CSS 类名、固定坐标或输入框视觉顺序。
- 类目未唯一匹配、字段缺失或页面出现未知必填项时，记录实际文案并暂停。
- “下一步”只用于完成当前页面校验，不得绕过错误。

### 3. 基础信息与规格

按当前页面顺序填写：素材语言、轮播图、标题、产地、主要材质、手机型号、当前颜色、包装图片/类型/形状、敏感属性、尺寸和重量。

- 产地是两级级联：先确认国家/地区，再确认省份；只显示国家而省份仍为“请选择省份”不算完成。
- 主要材质必须选择 `PC`；图片首图材质编码不能替代该属性。
- 当前任务只选择当前单色，不得把品牌的全部颜色合并到一个商品。
- 敏感属性和体积重量优先使用各自表头的“批量填写”：选择值、确认按钮启用、点击批量填写后，再逐行核验所有组合行。

已确认的页面映射：

- 配置 `iPhone 15` 对应页面候选 `iphone 15`；选择后必须确认规格表新增该型号。
- `PC` 对应页面展示 `PC PC(Polycarbonate)`；选择后输入框最终值必须为 `PC`。
- 颜色允许直接输入；必须确认输入框最终值和规格表新增的颜色行。候选项存在时可点击规范化，缺失时不得擅自改名或近似映射。
- 素材中心提示文件已存在时，关闭提示后勾选已有素材并确认。

### 4. SKU 信息表

SKU 表只产生“全部手机型号 × 当前颜色”的组合行。

1. SKU 分类在表头选择“单品”，点击 **SKU 信息区域** 的“批量填写”，再逐行确认已显示“单品”；不能只选表头，也不能误点敏感属性区域的同名按钮。
2. 申报价格、SKU 分类、建议零售价均在表头设置后分别点击对应的“批量填写”，禁止逐行重复填写。
3. 按当前任务的材质、工艺、单色、手机型号和图片编号生成每行 SKU 货号：

   ```text
   【材质编号】【工艺代码】-【手机型号】-【颜色编码】-【图片编号】
   ```

4. 建议零售价币种必须与配置一致；“制造商建议零售价（适用于美国）”保持为空；`fill_total_contents: false` 时“共计内含”保持为空。不得把包装重量或建议零售价写入错误字段。

### 5. SKU 预览图与详情图文

- SKU 预览图不使用批量填写。每个组合行都必须单独打开该行素材中心，点击素材卡片图片/缩略图（不是名称文本），确认“已选1个”和“确认”按钮可用；关闭后该行必须从“素材中心”变为“预览”。
- 默认每行绑定已核验轮播图的第一张，并覆盖全部组合行；不能只处理第一行或前两行。
- 若启用详情图文，按轮播图顺序添加同等数量的“图片”组件，复用同一份已确认轮播素材。每个组件只添加一次图片并确认预览存在，最后点击详情编辑器“保存”。
- 详情素材弹窗为空时依次执行：清空搜索词 → 关闭“仅展示可用” → 刷新 → 重开。仍为空则报告素材中心加载/可用性问题，不重复上传轮播图，也不能把空列表当作完成。

### 6. 合规声明、草稿保存与停止

1. 到达 SKU/预览/提交页后，定位“我已阅读并同意《商品合规声明》”前面的复选框。
2. 优先操作真实 `role=checkbox`/`input`；若控件为 `0×0` 或直接点击超时，点击同一标签内可见的小方框容器（如 `data-testid=beast-core-checkbox-checkIcon`）。禁止点击声明链接。
3. 读取真实控件 `checked` 状态，只有 `checked=true` 才算完成。
4. 点击“保存草稿”，确认出现“保存成功”，关闭提示并重载同一草稿。
5. 重载后逐项验收：国家和省份、轮播图数量、PC 材质、敏感属性、SKU 分类、两种价格及币种、SKU 货号、预览图覆盖率、详情组件顺序、合规勾选状态。
6. 汇总已填值、图片、价格、币种和未解决字段后停止。保存草稿或勾选声明不等于获准创建；最终“创建/提交/立即提交”必须等待用户即时确认。

合规信息（欧代、土代/GPSR 等）属于提交后的独立模块，只有配置有明确值且用户另行确认时才进入；不要在新建商品页猜填。

## 四、状态驱动等待与回退

- 不使用固定时长 sleep 作为正常流程。动作后立即读取对应完成条件：弹窗出现/消失、按钮启用、输入框最终值、规格或 SKU 行出现、上传进度消失且缩略图数量正确、URL/步骤标题变化或“保存成功”出现。
- 等待期间只观察，不重复点击；超时后重新读取 DOM 和可见错误文本，按当前步骤的重试上限处理，不用更长等待掩盖失败。
- 页面稳定且映射缓存命中时执行确定性动作；只有控件无法唯一匹配、候选变化、页面报错或验收失败时才进入 agent/人工回退。回退成功后更新缓存。

## 五、配置自适应与安全停止

页面实际字段优先于旧配置。发现标签、选项、图片路径或字段结构变化时，先记录“配置键 → 实际页面字段/选项”的差异；只有用户同意才回写 `listing.yaml`，保留原值并用注释或 `overrides` 记录，不删除未知配置项，也不把一次性文案硬编码成永久规则。

出现以下任一情况必须停止并给出缺口清单：

- 未登录、CAPTCHA、风控或要求敏感资料；
- 类目、字段、选项或颜色无法唯一匹配；
- 图片缺失、格式不符、素材中心无法确认或预览不完整；
- 报价、价格公式、颜色、工艺、图片材质编码或 SKU 不明确；
- 保存/重载验收失败；
- 最终提交前未获得用户即时确认。

不得通过接口、脚本注入或隐藏字段绕过页面验证。

详细配置键和解析约定见 [references/listing-schema.md](references/listing-schema.md)。
